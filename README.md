# 3DWorld

Лёгкая система визуализации для моделирования полёта (Qt5 + OpenGL + libQGLViewer).

Программа отображает небо с солнцем и облаками, рельеф (ESRI ASCII Grid), 3D-модели объектов (OBJ),
их траектории, ломаные 3D-линии, индикатор на лобовом стекле (ИЛС) с прицельными
метками целей. Данные приходят по UDP от внешней модели или читаются из текстового файла.

## Сборка

### Linux (Debian/Ubuntu)

```sh
sudo apt install qtbase5-dev libqt5opengl5-dev libglu1-mesa-dev
mkdir build && cd build
qmake ../3DWorld.pro
make -j$(nproc)
```

libQGLViewer (2.8) собирается из исходников в каталоге `QGLViewer/` вместе с
проектом, системный пакет `libqglviewer` не нужен. Чтобы использовать
системную библиотеку, запустите `qmake CONFIG+=system_qglviewer` — её версия
должна совпадать с заголовками в `QGLViewer/` (иначе будут ошибки линковки
вида `undefined reference to QGLViewer::QGLViewer(...)`).

### Windows

Библиотеки `QGLViewer2.lib` / `QGLViewerd2.lib` лежат в каталоге `libs/`,
проект собирается в QtCreator из `3DWorld.pro`.

## Запуск

```sh
./3DWorld                       # приём данных по UDP
./3DWorld examples/circle.txt   # воспроизведение траектории из файла
./3DWorld --terrain 43.35,42.44,60   # рельеф из интернета: широта, долгота, размер области, км
./3DWorld --terrain-stream 43.35,42.44   # подгрузка рельефа по ходу полета от начала координат
./3DWorld --record session.rec      # запись принимаемых UDP-пакетов
./3DWorld --play session.rec        # воспроизведение записи
```

Модели (`libs/*.obj`) и рельеф (`defaultTerrain.asc`) ищутся рядом с программой,
в текущем каталоге и на уровень выше, поэтому запускать можно и из каталога сборки.

### Тестовый источник данных

```sh
python3 tools/udp_test_sender.py --objects 3     # самолёты по окружностям + 3D линии
python3 tools/udp_test_sender.py --reset         # команда сброса траекторий
```

## Управление

| Клавиша | Действие |
|---|---|
| `1`…`9` | привязать камеру к объекту с индексом 0…8 |
| `PageDown` / `PageUp` | следующий / предыдущий объект (любое их число) |
| `P` | пауза / продолжение воспроизведения записи |
| `[` / `]` | перемотка записи на 10 с назад / вперёд |
| `Home` | воспроизведение записи сначала |
| `0` | свободная камера (мышь — вращение/перемещение QGLViewer) |
| `U` | камера сверху над объектом / обратно |
| `Insert` | вид назад |
| `T`/`G`, `F`/`H` | доворот камеры по тангажу / курсу |
| `W`/`S`, `A`/`D` | смещение камеры относительно объекта |
| `+` / `-` | масштаб сцены |
| `Q` | сброс положения камеры |
| `I` | включить/выключить HUD |
| `K` | включить/выключить небо (по умолчанию включено) |
| `Z` | окно настроек (небо, туман, сетка, ИЛС, рельеф, загрузка файлов) |
| стрелки | органы управления (отправляются объекту по UDP, порт 4998) |

## 3D-модели

Модели задаются в `view3DArea::readAllModels()`: код объекта, OBJ-файл и
реальная длина модели (масштаб подбирается по длине вдоль оси X; 0 — размеры в
файле уже в метрах). Оси модели: X — вперёд (нос), Y — вверх, Z — вправо.

| Код | Модель |
|---|---|
| 101, 102 | F-15 (`libs/f15.obj`) |
| 105 | конус (`libs/cone.obj`) |
| 106 | Ил-76 (`libs/il76.obj`) |

Материалы берутся из `.mtl` (цвет, блеск, прозрачность). Если модель содержит
уровни детализации `lod0`, `lod1`, … — рисуется только самый детальный.
Столбец «масштаб» текстового файла умножает размер модели.

## HUD

`view3DHud.cpp` — индикатор на лобовом стекле, отображается при камере,
привязанной к объекту (`1`…`9`):

- шкала тангажа через 5° (ниже горизонта — пунктир), поворачивается по крену;
- символ продольной оси «W» и маркер вектора скорости (по `vc_x/vc_y/vc_z`,
  при их отсутствии — по углам атаки и скольжения);
- шкала курса сверху, скорость (км/ч) слева и высота (м) справа;
- шкала крена, число M, перегрузка G, угол атаки α;
- ромбы целей (остальные объекты) с дальностью в км; цели вне поля
  зрения прижимаются к краю экрана.

## Рельеф

Карта высот в формате ESRI ASCII Grid (`defaultTerrain.asc`, загрузка другой
карты — окно настроек `Z`). Узлы сетки переводятся в метры в касательной
плоскости с центром в середине карты: X — на север, Z — на восток, Y — высота.
Рельеф освещается солнцем, цвет зависит от высоты и крутизны склона
(вода, низменность, предгорья, горы, скалы, снег). За пределами карты земля
продолжается плоскостью до горизонта, вдали — воздушная дымка.

### Рельеф из интернета

Окно настроек (`Z`) → «Рельеф из интернета»: широта, долгота центра области и
её размер в км (или параметр `--terrain широта,долгота[,км]`). Высоты берутся из
открытого набора [AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/)
(формат Terrarium, без ключа доступа, весь мир, разрешение до ~30 м).
Загруженные тайлы кэшируются, готовая карта сохраняется как `.asc` в
`~/.cache/3DWorld/terrain/` и может открываться без интернета кнопкой «ландшафт».
Глубины моря не отображаются (уровень воды 0). Используются системные
настройки прокси.

### Подгрузка рельефа по ходу полёта

Галочка «подгрузка по ходу полета» (или `--terrain-stream широта,долгота`)
включает сцену без фиксированных границ: вокруг камеры держится область 9×9
тайлов (уровень 11, ~14 км на тайл в средних широтах, шаг сетки ~200 м),
при движении впереди догружаются новые тайлы, далёкие выгружаются. Широта и
долгота задают точку начала координат сцены (x = 0, z = 0); если модель
передаёт в объекте `fi0_geo`/`lam0_geo` (рад), используется эта точка.
Тайлы кэшируются в `~/.cache/3DWorld/terrain/`, поэтому повторный полёт над
тем же районом работает без интернета.

Подгрузка идёт двумя слоями: подробные тайлы (уровень 11, 9×9) вокруг камеры
и крупные (уровень 9, 7×7, обзор около ±200 км) вдали; крупные тайлы не
рисуются там, где уже есть подробные.

Проверка: `python3 tools/udp_test_sender.py --line --speed 1500` и
`./3DWorld --terrain-stream 43.35,42.44`, затем клавиша `1`.

### Спутниковые снимки

Галочка «спутниковые снимки» (по умолчанию включена) накладывает снимки на
подгружаемый рельеф и на карту, загруженную из интернета. По умолчанию —
[Sentinel-2 cloudless 2016](https://s2maps.eu) (EOX IT Services GmbH,
CC BY 4.0, разрешение ~10 м); подпись источника выводится в углу экрана.
Другой источник тайлов Web Mercator задаётся переменными окружения:

```sh
TERRAIN_IMAGERY_URL="https://.../{z}/{y}/{x}.jpg" TERRAIN_IMAGERY_ATTRIBUTION="..." ./3DWorld
```

Снимок для карты сохраняется рядом с `.asc` под тем же именем (`.jpg`).
Для своей карты можно положить рядом `имя.jpg` или `имя.png` — снимок,
охватывающий ту же область (регулярная сетка по широте и долготе, верх — север).

## Небо

`view3DSky.cpp`: градиентный купол вокруг камеры (с высотой небо темнеет), солнце
с ореолом и слой процедурных облаков на высоте 9000 м, которые медленно
дрейфуют по ветру. Солнце — источник света для 3D-моделей, туман при включённом
небе окрашивается в цвет горизонта. Положение солнца, высота облаков и скорость
ветра задаются в `View3DSky`.

## Формат текстового файла

Одна строка — одна точка, столбцы разделены табуляцией:

```
код  масштаб  время,с  x,м  y,м  z,м  psi,град  tan,град  gamma,град
```

## Протокол UDP

Приём на порту `7030`. Пакет начинается с заголовка `THRequest`
(`id`, `typeRequest`, `size`, `tics`, `dtTics` — по `uint32`), далее для пакетов
с данными идут поля `TMRequest` (`compressed`, `err`, `sizeBuf`) и буфер данных
(до 2048 байт). Типы пакетов (`TTypeHead`, см. `visudp.h`):

| Тип | Значение | Содержимое буфера |
|---|---|---|
| `PARAM_OBJ` | 0 | `TSendVehicleVisSimple` — параметры объекта (новый `id` добавляет объект) |
| `COMMAND` | 2 | `TCRequest` — `TC_RESET` / `TC_CLEAR` очищают траектории |
| `PARAM_ARRAY` | 4 | `TSendArrayVisSimple` — массив географических точек |
| `LIST_VECTOR` | 5 | `TSendListVectorsVisSimple` — ломаная линия из точек `vec3` |
| `PARAM_OBJ_LIST` | 6 | `uint32` кол-во + массив `TSendVehicleVisSimple` (до 8 объектов в пакете) |

### Много объектов

Объекты ищутся по `id` через хеш-таблицу, буфер приёма сокета увеличен до 8 МБ,
несколько объектов можно передавать одним пакетом `PARAM_OBJ_LIST`. При
отрисовке объекты вне поля зрения отбрасываются; крупные на экране (≥ 6 px)
рисуются полной моделью (не более 64 ближайших), остальные — метками.
Объекты с неизвестным кодом модели показываются метками. Траектории хранятся
массивами и рисуются массивами вершин; общий бюджет — 400 000 точек на все
объекты. HUD показывает ромбы 64 ближайших целей и дальность — 12 ближайших.
Проверка: `python3 tools/udp_test_sender.py --swarm --batch --objects 2000`.

### Сглаживание, удаление объектов, запись сеанса

Окно настроек → «Сеть»:

- **сглаживание движения** — между пакетами положение объекта экстраполируется
  по скорости `vg_x/vg_y/vg_z` (если она передаётся), иначе интерполируется
  между двумя последними пакетами с запаздыванием на один интервал; углы —
  по кратчайшей дуге;
- **удалять без данных, с** — объект, от которого нет пакетов дольше заданного
  времени, удаляется вместе с траекторией (0 — не удалять, по умолчанию 10 с).
  Камера привязана к `id` объекта и не «перескакивает» при удалении других;
- **запись** — принимаемые пакеты пишутся в `Документы/3DWorld/session_*.rec`
  (формат: `3DWREC01`, затем записи «время, мс (int64) + размер (uint32) + пакет»);
- **воспроизвести** — проигрывание записи; скорость — «Множитель времени»,
  `P` — пауза, `[`/`]` — перемотка, `Home` — сначала.

Частота отрисовки по умолчанию 60 Гц (окно настроек, «Частота кадров»), время
сцены идёт по реальным часам и не зависит от частоты кадров.

Размеры пакета проверяются: короткие пакеты отбрасываются, число точек
ограничивается фактическим размером данных. Пример формирования пакетов —
`tools/udp_test_sender.py`.
